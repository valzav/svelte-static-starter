# Design system

The rules and contracts behind `site/src/lib/styles/tokens.css` and
`site/src/lib/components/`. This file carries the reasoning; the running
[`/styleguide`](../site/src/routes/styleguide/+page.svelte) route carries the current truth,
because it renders the real tokens and the real components.

Read [`guidelines.md`](guidelines.md) for brand-level direction — voice, logo, imagery — which is
deliberately empty in this template.

## How this file stays honest

The token tables below are **generated** from `tokens.css`:

```sh
node scripts/build-token-reference.mjs           # rewrite the tables
node scripts/build-token-reference.mjs --check   # fail if they are stale (CI runs this)
```

Everything outside the `tokens:start` / `tokens:end` markers is written by hand. When you add a
component, add its contract to the catalogue below in the same change.

## Token architecture

Three layers, all in one file, each resolving to the one above it. The layer a token belongs to is
declared by a `/* [layer] */` comment, which is also what the generator and the style guide read.

1. **Primitive** — raw palette, type scale, spacing scale, radii, durations. A component that
   references a primitive directly is a bug: it has skipped the layer that gives the value meaning.
2. **Semantic** — role names (`--ds-bg`, `--ds-fg`, `--ds-accent`, `--ds-border`). Dark is the
   default on `:root`; `[data-theme='light']` redefines **only this layer**. Theming works before
   hydration and without JavaScript because it is nothing but CSS custom properties.
3. **Component** — per-component aliases. They exist so one component's spacing or colour can move
   without touching the palette, and so a component's full surface is visible in one place.

### Rules

- Components reference tokens only. No raw colour, size, or font name in a `.svelte` file.
  `tests/e2e/contrast.spec.ts` asserts this and fails the build if it slips.
- A themed container re-declares `color`, not only `background`. Inheritance carries the *computed*
  colour down, so a light section inside a dark page keeps the dark theme's text without it. This
  is guarded by a test that fails when the declaration is removed.
- Adding a component usually means adding component-layer tokens. That keeps `tokens.css` long on
  purpose: the length lives in one reviewable place instead of scattering through components.
- Changing the palette means changing the primitive layer and, where roles shift, the semantic
  mappings. Components should not move.

See [ADR-0005](../docs/architecture/adr/0005-design-tokens-as-layered-css-custom-properties.md)
for why this shape rather than a utility framework or a UI kit.

## Component catalogue

Every component lives in `site/src/lib/components/`. `ui/` holds primitives that know nothing about
the page; `layout/` holds the page chrome. None of them contain literal copy — content arrives as
props from `src/lib/content/` (ADR-0004).

### Primitives

| Component | Props | Contract |
| --------- | ----- | -------- |
| `Section` | `id`, `kicker?`, `title?`, `lead?`, `level?` (1 \| 2, default 2), `theme?` (dark \| light), `align?` (start \| center), `decor?`, `children?` | The page's structural unit. `level={1}` renders the single `h1`; everything else is `h2`. `theme="light"` repaints background *and* colour. `decor` paints behind the content and is clipped to the section. |
| `ActionLink` | `href`, `variant` (primary \| secondary \| link), `layout?` (default \| stacked), `title?`, `description?`, `children?` | Every call to action. Adds `rel="noopener"` to external URLs only, matching protocol-relative and case-insensitive schemes. `layout="stacked"` renders a card-sized target with a title and description. |
| `ContentCard` | `title`, `body?`, `numbered?`, `children?` | A titled block. `numbered` adds an ordinal drawn from CSS counters, so the numbers stay correct when cards are reordered. |
| `ColumnList` | `items` (`Column[]`), `layout?` (default \| three-column) | Parallel items of equal weight. Reach for it instead of a grid of `ContentCard` when the items are a list, not a set of destinations. |
| `Pill` | `children?` | A small non-interactive label. Never a button — if it does something, it is an `ActionLink`. |
| `Metric` | `value`, `label`, `disclosure?` | A single number. Counts up on scroll; renders its final value with JavaScript off or reduced motion on. A `*` suffix on the label pairs with `disclosure`. |
| `Reveal` | `delay?`, `children` | Fades and rises its children on intersection, once. Renders visible with JavaScript off or reduced motion on. Wrap groups, not individual words. |
| `Accordion` | `items` (`FaqItem[]`) | Native `details`/`summary`, so it opens without JavaScript. One open item at a time via the `name` attribute. |
| `AccordionItem` | `item`, `groupName` | One disclosure. Marks `status: 'generated'` answers with `data-replace-me`; it knows nothing else about status. |
| `Logo` | `variant` (full \| symbol), `theme` (dark \| light) | `theme` names the background the mark sits **on**, so `dark` carries light ink. |
| `LogoGrid` | `entries` (`LogoEntry[]`), `showLabels?` | Equal-geometry tiles that do not overflow on mobile. |
| `LogoTile` | `entry`, `showLabels?` | One mark. Tints a monochrome SVG with a CSS mask so a single asset works on both themes; `status: 'stub'` entries fall back to a plain image. |

### Layout

| Component | Props | Contract |
| --------- | ----- | -------- |
| `Header` | `navigation`, `contact` | Fixed anchor navigation with the contact link separated out. Its height is `--ds-header-height`, which `base.css` uses for both `scroll-padding-top` and the `main` offset — change it in one place. |
| `Footer` | `logo`, `socialLinks`, `legalLinks`, `disclaimer` | Renders a link without an `href` as plain text rather than a dead anchor, which is how pending content stays visible on staging without shipping a broken link. |

### Element choice

- Something that navigates or acts is an `<a>` or a `<button>`. Never a `div` with a handler.
- Native elements before ARIA. `Accordion` uses `details`; adding `role`/`aria-expanded` on top of
  it would fight the browser, and a test asserts they are absent.
- Tap targets are at least `--ds-interactive-min-target` (44px).

## Anti-patterns

- A raw hex, `rgb()`, pixel size, or font name inside a `.svelte` file.
- A component reaching past the semantic layer into a primitive.
- A themed container that sets `background` without `color`.
- Copy written into a component instead of `src/lib/content/`.
- A new component that duplicates an existing one with one prop changed. Add the prop.
- `!important`, or a selector that outranks a component's own scoped styles.

## Pre-delivery checklist

1. `pnpm lint`, `pnpm check`, `pnpm test:unit`, `pnpm test:e2e`, `pnpm verify:robots` pass.
2. `pnpm content:check` exits 0, so no stub or draft copy can publish.
3. `node scripts/build-token-reference.mjs --check` passes.
4. The change reads correctly in both themes — check `/styleguide`, which renders both.
